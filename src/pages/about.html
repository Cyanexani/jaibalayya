The project

Why
Metro?

Because a genuinely different idea about how a phone should work was shipped, refined, loved by a minority, and then switched off. Ideas do not stop being good when a company stops selling them.

What this is

Metro OS is an independent, open-source recreation and preservation project inspired by the Metro design language and the mobile experience of the Windows Phone era. Its purpose is to rebuild the interaction model — the tiles, the typography, the transitions, the way information arrives before you go looking for it — as a modern, original implementation that runs on hardware people actually own.

It is written from scratch in Kotlin, ships as an Android launcher and system-UI package, and contains no code, assets or branding from any proprietary system. Where the original had a look, we have our own drawing of it. Where the original had a behaviour, we have our own implementation of it.

This is not nostalgia software. It is an argument that the industry abandoned a better idea, made in the only form that matters: working code.

What this is not

Metro OS is not affiliated with, endorsed by, sponsored by or connected to Microsoft Corporation. It is not Windows, not Windows Phone, not Windows Mobile, and not a continuation of any Microsoft product line. It does not use Microsoft's trademarks, logos, icons, fonts or proprietary assets as its own branding.

Those names appear on this site in exactly one way: to describe the design era this project preserves, which is fair descriptive use. “Windows”, “Windows Phone”, “Metro” and related marks belong to their respective owners. Metro OS uses its own name, its own four-part rhombus mark and its own icon set throughout — including in the product itself.

It is also not a ROM, not a fork of Android, and not a replacement operating system in the literal sense. “OS” describes the scope of the experience — shell, system UI and a full application suite — not a claim to have written a kernel.

What we hold to

Six principles.

01

Content, not chrome

If a pixel is not information, it should not be lit. No bevels, no faux depth, no decorative gradients standing in for hierarchy.

02

Typography is the interface

Size and weight do the work that borders and boxes do elsewhere. A screen should be readable across a room.

03

Motion means something

Every transition says where you came from. If an animation is not answering that question, it is removed.

04

Nothing phones home

No analytics, no crash reporting, no advertising identifier, no account. This is not a setting; it is a constraint on the codebase.

05

Original work only

Every icon, wallpaper, string and line of code in this project is ours or properly licensed. We rebuild ideas; we do not copy assets.

06

Usable beats impressive

Contrast, focus order and reduced-motion support ship with the feature. An effect that costs somebody access is not a feature.

How it got here

Three years
of stubbornness.

It started as a launcher that drew rectangles. The rectangles were the wrong size, the animations were wrong, and the whole thing fell over if you rotated the phone — but the first time a weather tile flipped over on its own, the point was made.

What followed was the unglamorous part: a back stack that behaves, a tile scheduler that does not eat the battery, a notification listener that survives OEM power management, and an app suite written to the same rules rather than bolted on.

Metro OS is at preview 0.5. Eight of thirteen apps ship, the shell is stable enough to live on, and the parts that are not finished are named on the roadmap instead of hidden.

Reasonable questions

Before you ask.

Recreating an interaction model and a visual style with original code and original assets is ordinary practice in software. What is not acceptable is passing yourself off as somebody else, and we do not: separate name, separate mark, separate icons, separate code, and a disclaimer on every page. No Microsoft binaries, fonts or images are redistributed by this project.

Yes. Metro OS is a launcher and system-UI layer on top of stock Android — every app you have keeps working, keeps updating and keeps its own security posture. Nothing is rooted, patched or sideloaded on your behalf.

Because the interesting part was never the colours. Live Tiles, the back stack, the search key, the people-first model and the transition grammar are behaviours, and behaviours need code. A theme would give you the postcard without the place.

Check with whoever manages it first. Metro OS is a preview build from a volunteer project with no warranty and no support contract — it should not be the thing standing between you and a work call.

Install a nightly and file what breaks. That is genuinely the most useful thing most people can do. After that: translations, documentation, design, and the two apps nobody has started.
